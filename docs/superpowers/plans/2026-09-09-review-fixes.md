# Review fixes implementation plan

Approved scope: docs/reviews/2026-09-09-app-review.md. User requested everything in the listed five-stage order with complexity-based subagents.

Global constraints: Ponytail full; reuse existing architecture and dependencies. Test failures before fixes, smallest meaningful regression checks, no real crontab, live webhook, installation, or system changes in tests. Keep all edits in current isolated worktree. No commit/push/deploy is needed to deliver the changes. Review each stage before starting the next. Existing Go race suite and vet passed immediately before this implementation turn. Production PowerShell is absent locally; explicitly report unverified legacy runtime coverage.

### Task 1: Protect persistence
Files: internal/cron/crontab.go and tests; internal/history/history.go, internal/retention/retention.go and tests; internal/tui/envedit.go, messages.go, root.go and relevant overlay tests; legacy src/Core.psm1 and src/Runner.psm1 as required for history interoperability; internal/runner/runner.go for persistence warnings.
Implement: reject ambiguous failed crontab reads, preserve diagnostics and recognize positively identified no-crontab. Serialize history append and prune transactions across processes, including supported legacy writers (or conservatively suppress unsafe mixed-writer pruning with a documented enforceable policy). Keep env editor open on save failure, preserve dirty buffer, atomic private file save. Surface log/history persistence failure separately from script exit status to all runner consumers without exposing secrets. Do not silently certify a missing log.
Checks: fake crontab stderr failure cannot write; known absent crontab can initialize. Concurrent append/prune loses no rows using deterministic synchronization. Env failed save retains buffer and original file, successful save closes and preserves private mode. Runner failed log/history persistence is observable and does not falsely change script execution result.
Interfaces: maintain existing frontend signatures where possible; introduce minimal explicit save-result and persistence-warning data if needed. Record changes for later tasks.

### Task 2: Serialize preparation and queued runs
Files: internal/tui/runctl.go, runview.go, actions.go, depsview.go, messages.go, confirm.go, root.go, task.go and tests; runner/dependency context plumbing only where needed.
Implement: synchronously reserve active state before dependency scan and retain ownership until run start/cancel/failure. Queue subsequent requests, including while launch is pending. Quit and kill during preparation must cancel/await and not launch abandoned work. Route queued scripts through same dependency preparation as direct requests. Delayed/stale results must not overwrite newer ownership. Display preparation state and queue count/next name. Error messages remain visible during active runs.
Checks: rapid different-script requests, same-script request, queue dependency checks, cancellation during scan/launch, quit, missing queued scripts, stale async messages, normal/failing/timeout run finalization. Use existing hermetic harness. Keep state model minimal, no generic job framework.
Interfaces: stage 1 env save ownership must be preserved. Report active state and new messages for subsequent stage implementers.

### Task 3: Correct discovery and refreshed state
Files: internal/scripts/discover.go and tests; internal/tui/root.go, messages.go, fleet.go, statusbar.go, schedules.go, history.go, runview.go and tests; internal/deps/pyscan.go, install.go and tests; internal/mcp/ops.go and internal/cli/cli.go if per-script status windows need correction.
Implement: unique case-insensitive names with collision-safe suffixes including naturally numbered candidates; statuses from complete latest-per-script data rather than 200/2000 global tail; cheaply notice external history changes and update Fleet/History off event/render loop; context reflects current view selection. Delegate requirements manifests including versions, extras and includes to pip (simplest safe policy: invoke manifest install on preparation rather than reimplement pip); ensure every frontend participates. Cache selected script env metadata outside rendering and refresh on relevant changes. Correct source-update messages across TUI/API/README to explain rebuilding rather than claiming restart installs pulled source.
Checks: three-way/natural/case collision; quiet script status after >200 other runs; external completion refresh; current Schedules/History context; existing installed version with changed requirement and included manifest triggers installation; env metadata refresh; accurate source update text. Update affected goldens only after semantic assertions pass.

### Task 4: Bound rendering and run buffers
Files: internal/tui/history.go and tests/benchmarks, internal/tui/anim.go; internal/mcp/ops.go and tests; internal/runner/runner.go and tests.
Implement: cache filtered/reversed History ordering on data or scope change, render only visible rows; avoid animation for invisible changes. Replace complete API output accumulation with bounded fallback tail; regular output uses existing disk tail. Bound resource series during long runs while preserving full-run averages/maxima and meaningful representative chart shape. No dependency or new storage layer.
Checks: benchmark 200 and 50000 rows at 120x40 before/after under same conditions, warmed render allocations not proportional to rows. Scope/invalidation tests; bounded fallback with huge/Unicode lines and missing log; resource stream bounded over long sample sequence with exact aggregate stats. Preserve stage 1 persistence warnings.

### Task 5: UI functionality and aesthetics
Files: internal/tui/runview.go, keys.go, root.go, cards.go, palette.go, anim.go, theme and tests/goldens; internal/config/config.go and tests; README.md/config.json.example as needed.
Implement: below 80 columns full-width Run list/output switched by Tab with clear visible focus and correct mouse hit targets, minimum 40x10 remains usable. At 80 columns preserve split layout. Remove duplicate recent-card status word, reclaim name space; shorten age labels consistently. Deduplicate pane/footer hints while reserving ? help and : commands and combining navigation hints. Fleet f says failures, History f says scope. Reuse palette for searchable theme selection and explicit atomic Save action preserving other config fields; reduced-motion configuration disables fades/marquees/breathing and high-frequency ticks while conveying progress. Retain semantic text/symbol cues and monochrome compatibility. Stage 2 already supplies preparation/queue/errors: verify integrated UX.
Checks: pinned 40x10,60x24,80x24,120x40 frames, both narrow focuses, mouse/keyboard navigation, ASCII/no color; narrow hints discoverable; theme filter/select/save and failed save preserves config; reduced motion shows stable readable status and eventually expires messages without 60fps timers. Update goldens deliberately; full suite/race/vet and final broad code review.
